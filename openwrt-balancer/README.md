# Synet Remnawave → OpenWrt PassWall2 (Xray JSON)

**Экспериментальный установщик v0.2 (RAM-режим). Не протестирован на реальном маршрутизаторе.**

Устанавливает отдельный Xray-core на OpenWrt и использует **ту же** подписку `synet` из PassWall2 (`User-Agent: Happ/1.0`). Сохраняет готовый `routing.balancers`, `burstObservatory` и `outbounds` из Xray JSON. Создаёт локальный SOCKS5 на `127.0.0.1:19080` и добавляет в PassWall2 узел **Synet eGames JSON (local)**.

**Никаких изменений текущего TCP/UDP-узла, DNS, firewall, маршрутизации и настроек других подписок автоматически не делает.** Выбор созданного узла осуществляется вручную в LuCI, только после тестирования.

## Установка (OpenWrt, root)

Проверьте код перед запуском: [install.sh](install.sh).

```sh
wget -qO /tmp/synet-openwrt.sh https://raw.githubusercontent.com/LendryHD/remnawave-xhttp-hy2/main/openwrt-balancer/install.sh && sh /tmp/synet-openwrt.sh
```

Скрипт:

1. Находит уже существующую подписку `synet` в UCI PassWall2, спрашивает подтверждение. Если её нет — запрашивает HTTPS-ссылку интерактивно, без публикации в GitHub.
2. Проверяет `curl` и свободное место. Устанавливает недостающий `jq` через `opkg`. Если во flash достаточно места — использует обычный `xray-core`; иначе выбирает RAM-режим с распаковкой бинарника из `.ipk` в `/tmp`, **без `opkg upgrade`** и без смены маршрутизации.
3. Скачивает подписку с `User-Agent: Happ/1.0`. **Поддерживает только один JSON-объект полной конфигурации Xray** с `routing.balancers`. При ином формате не пытается его угадывать и не активирует узел. В частности, ссылки `vless://` или base64 не поддерживаются.
4. Заменяет входящие SOCKS/HTTP из клиентского Xray JSON **одним** локальным SOCKS на `127.0.0.1:19080` (это необходимо для предотвращения конфликтов портов), сохраняя исходный тег SOCKS, outbound'ы, маршрутизацию, observatory и DNS из подписки.
5. Выполняет `xray run -test -c ...` перед изменением рабочей конфигурации. При неуспехе оставляет предыдущую. Настраивает `procd` и таймер cron раз в 15 минут.
6. Добавляет узел PassWall2 с локальным SOCKS5, **не назначая его активным**.

## RAM-режим для роутеров с малым /overlay (экспериментально)

Если `xray` ещё не установлен, а в `/overlay` меньше **36 МБ** свободного
места, установщик выбирает **RAM-режим** автоматически. Он проверяет, что
архитектура `aarch64`, свободно не менее **55 МБ в /tmp** и доступно
не менее **75 МБ оперативной памяти**. В этом режиме:

- `opkg update` проверяет индекс подписанных feed OpenWrt; `opkg download xray-core` скачивает пакет во временную память;
- из `.ipk` извлекается **только исполняемый файл** в `/tmp/synet-balancer/xray`; `opkg install xray-core` не выполняется;
- служба procd при загрузке роутера снова скачивает бинарник, если он исчез после перезагрузки; при отсутствии интернета повторяет загрузку с интервалом 30 секунд;
- подписка, служебные скрипты и JSON остаются в `/etc/synet-balancer/` и `/usr/libexec/synet-balancer/` на постоянном хранилище; пароль подписки в вывод не печатается.

В `/tmp` могут одновременно временно находиться архив пакета (~10–20 МБ)
и распакованный Xray (~27 МБ), поэтому дополнительно расходуется RAM.
При одновременной работе sing-box и Xray возможна нехватка памяти,
особенно на роутере с 256 МБ RAM. **На реальном OpenWrt 24.10.4
режим ещё не протестирован.** Не используйте `--force-space`,
`--force-depends` или общий `opkg upgrade`.

Для оценки ресурсов: `df -h /overlay /tmp; free -m`.

## Проверка

```sh
/etc/init.d/synet-balancer status
curl --max-time 20 --socks5-hostname 127.0.0.1:19080 https://api.ipify.org
```

После успешной проверки откройте **PassWall2 → Основные настройки → TCP-узел** и выберите `Synet eGames JSON (local)`. Прежде чем включать маршрутизацию всей сети, проверьте один клиент и отсутствие циклических маршрутов (если в PassWall2 включён перехват локального трафика роутера). У вас по-прежнему должны работать прежние профили в качестве резервного выбора.

Синхронизация вручную:

```sh
/usr/libexec/synet-balancer/update.sh
```

## Предупреждения и ограничения

- Это интеграционный вариант, а **не нативный импорт балансировщика PassWall2**. PassWall2 использует локальный SOCKS-клиент; балансировку выполняет отдельный процесс Xray-core.
- Скрипт сохраняет **один** полный Xray JSON, отдаваемый подпиской. Если сервер отдаёт один профиль (например, только VLESS), скрипт не создаёт автоматически второй профиль Hysteria2. Для нескольких независимых профилей потребуется расширение установщика или отдельные endpoint'ы формата, но не обязательно вторая учётная запись подписки.
- Не следует ожидать полноценной UDP-передачи через любую конфигурацию PassWall2 → SOCKS, особенно для игр/QUIC: это зависит от конкретной версии и настроек PassWall2.
- Принудительная смена Xray-core может оказаться несовместимой с частью VLESS/Hysteria2-конфигураций. Если `xray -test` вернёт ошибку, установщик остановится. Не используйте `--force-depends`.
- Параллельный запуск PassWall2 + Xray потребует дополнительной оперативной памяти; в RAM-режиме потребуется память и для самого бинарника в /tmp. Для малого роутера проверьте ресурсы.
- Если в PassWall2 перехватывается локальный `OUTPUT`, может возникнуть петля проксирования Xray. По этой причине **автоматическое переключение активного узла запрещено**.
- Нельзя вводить ссылку подписки в публичные issue или добавлять её в репозиторий: это секрет.

## Безопасность

Полная ссылка хранится только на роутере в `/etc/synet-balancer/curl.conf` с режимом `0600`, каталог `0700`. В URL для `curl` используются аргументы `-K` без токена в командной строке. Файл `/etc/synet-balancer/active.json` содержит секреты клиентских подключений: не публикуйте его.

В случае неудачной проверки свежего JSON прежняя рабочая конфигурация не затирается. Бэкап: `/etc/synet-balancer/previous.json`.

Эта версия — первый безопасный прототип. Она не гарантирует полную совместимость неизвестной выдачи Remnawave или отсутствие сетевых циклов на конкретной конфигурации OpenWrt.
